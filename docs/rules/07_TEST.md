# 07. 테스트 전략

> 문서 상태: ✅ 완료 (2026-11-25)

## 1. 테스트 범위

### 작성할 테스트 수준
- 상태: ✅ 결정
- 선택지 (복수 선택):
  - **단위 테스트** — 도메인 로직, 유틸 함수
  - **통합 테스트** — API 엔드포인트, DB 연동
  - **E2E 테스트** — 브라우저 시나리오
  - **없음** — 프로토타입 단계, 수동 확인만
- 결정:
  - **단위 테스트**: core 순수 함수, LLM 경계(가짜 transport로 공급자 응답·오류 재현), 설정, **core import 규칙 검사** (core가 repositories·llm·sources·DB 드라이버·HTTP 클라이언트를 import하지 않는지)
  - **통합 테스트**: ① 핵심 흐름 1개 — 글 등록 → 추천 저장 → SSE 수신 (LLM은 가짜 클라이언트) ② repository SQL — 매칭 후보 조회 등은 실제 DB로 검증
  - E2E 없음 (데모 페이지는 수동 확인)
- 이유: 매칭 품질은 평가 스크립트가 따로 재므로, 테스트는 규칙이 깨지지 않는지와 SQL·연결이 실제로 도는지에 집중한다. 3일 일정에 E2E는 부담
- 결정일: 2026-11-25

### 테스트 우선순위 (무엇을 반드시 테스트하는가)
- 상태: ✅ 결정
- 결정:
  1. 매칭 정렬 (사전식 단계 순서, 직무 B등급은 A가 3개 미만일 때만)
  2. 정규화 병합 규칙 (LLM이 기준을 덮어쓰지 못함, 근거 구절 검사, 수동 보정 우선)
  3. 산업 등급·계열 판정 (한 산업 = 여러 계열)
  4. 게이트·병합 (본문 명시 > 입력 필드 > 본문 추론)
  5. core import 경계
- 결정일: 2026-11-24

## 2. 도구

### 테스트 프레임워크
- 상태: ✅ 결정
- 선택지 예: JUnit 5 + AssertJ / Vitest / Jest / pytest / Playwright(E2E)
- 결정: pytest. async repositories·services 테스트용으로 비동기 테스트 플러그인(pytest-asyncio 또는 anyio)을 추가한다. 프론트는 테스트 없이 `tsc --noEmit` 타입 검사만
- 결정일: 2026-11-24 (비동기·프론트 보완 2026-11-25)

### 테스트 DB / 외부 의존성 처리
- 상태: ✅ 결정
- 선택지: 인메모리 DB(H2 등) / Testcontainers / 모킹 / 실제 개발 DB
- 결정:
  - LLM은 실제로 호출하지 않는다 — transport·sleep 주입으로 가짜 응답 사용 (현재 구현 방식)
  - DB: **Compose Postgres에 별도 테스트 DB(`bootq_test`)** — 테스트 시작 시 마이그레이션 적용, 테스트마다 트랜잭션 롤백. CI는 GitHub Actions의 Postgres 17 서비스 컨테이너로 동일하게
  - 평가는 DB·LLM 없이 고정 슬롯 JSON + 고정 캠프 데이터로 `core.matching` 직접 호출
  - 테스트는 git 제외 데이터(`data/private/`, `data/raw/`)를 읽지 않는다 — 고정 픽스처 사용
- 이유: 개발 DB와 같은 PostgreSQL 17이라 JSONB·배열 동작이 같고, Testcontainers 의존성을 늘리지 않는다
- 결정일: 2026-11-25

## 3. 운영 규칙

### 커버리지 목표
- 상태: ✅ 결정
- 선택지: 목표 없음 / 핵심 로직만 측정 / 전체 N% 이상
- 결정: **목표 숫자 없음.** 대신 1장 "테스트 우선순위" 5항목은 반드시 테스트가 있어야 한다
- 결정일: 2026-11-25

- 결정일: 2026-11-25

### AI 개발 시 테스트 규칙
- 상태: ✅ 결정
- 결정:
  - AI는 기능을 구현할 때 해당 테스트를 함께 작성하고, **전체 테스트 통과를 확인한 후** 완료 보고한다
  - 테스트 데이터에는 원본 유저 글·회사 원본 데이터를 쓰지 않고 재작성 샘플만 쓴다
- 결정일: 2026-11-25
