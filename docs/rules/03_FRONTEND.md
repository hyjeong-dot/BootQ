# 03. 프론트엔드 설계 규칙

> 문서 상태: ✅ 완료 (2026-11-25)
> 프론트엔드가 없는 프로젝트라면 이 문서 전체를 ➖ 해당없음 처리한다.

## 1. 기본 구조

### 렌더링 방식
- 상태: ✅ 결정
- 선택지: SPA(CSR) / SSR / SSG / 서버 렌더링 GUI(NiceGUI 등)
- 결정: **정적 HTML 1장 + TypeScript(ES 모듈, tsc 컴파일)**. FastAPI `StaticFiles`로 API와 같은 출처에서 서빙(CORS 불필요). SSE 응답은 **JSON**
- 이유: 실서비스에서는 커뮤니티 사이트가 우리 API를 불러 토스트를 그리므로 JSON이 현실적인 연동 계약이다. 데모가 그 계약을 그대로 증명하고, TS 타입이 API 응답과 맞물린다
- 검토한 대안: Jinja2 서버 렌더링 — 추천이 SSE로 뒤늦게 오므로 클라이언트 JS가 어차피 필요하고, SSE로 HTML 조각을 보내면 응답이 우리 화면 전용이 됨 (99_DECISIONS.md 폐기 방안)
- 결정일: 2026-11-25

### 라우팅 규칙
- 상태: ➖ 해당없음
- 결정: 페이지 1장(`/`). 글 입력·토스트·피드백이 한 화면에 있음
- 결정일: 2026-11-25

### 폴더 구조
- 상태: ✅ 결정
- 결정:
```
frontend/
├── index.html        # 글 입력 폼 + 토스트 영역
├── popup.css         # 목업 CSS 재사용
├── src/
│   ├── main.ts       # 진입점, 이벤트 연결
│   ├── api.ts        # 글 등록, SSE, 피드백 호출
│   ├── toast.ts      # 토스트·카드 렌더링
│   └── types.ts      # API 응답 타입
├── dist/             # tsc 출력 (git 제외)
├── package.json
├── package-lock.json
└── tsconfig.json
```
- 결정일: 2026-11-25

## 2. 상태 관리

### 서버 상태 (API 데이터)
- 상태: ✅ 결정
- 선택지: TanStack Query / SWR / 직접 fetch
- 결정: **`fetch` + `EventSource` 직접** 사용
- 이유: 호출이 글 등록·SSE·피드백 3개뿐이라 캐시 라이브러리가 필요 없음
- 결정일: 2026-11-25

### 클라이언트 상태 (UI 상태)
- 상태: ➖ 해당없음
- 선택지: 컴포넌트 로컬 state만 / Zustand / Jotai / Redux Toolkit
- 결정: 상태 라이브러리 없음 — 모듈 내 변수 + DOM 직접 조작
- 이유: 상태가 토스트 카드 3장 분량
- 결정일: 2026-11-25

## 3. 스타일링

- 상태: ✅ 결정

- 결정: 목업 CSS 재사용 (일반 CSS 파일)
- 이유: 기존 팝업 목업을 그대로 쓰기로 함
- 결정일: 2026-11-24

### 디자인 기준
- 상태: ✅ 결정
- 결정: 인턴십 프로젝트의 팝업 목업(데스크톱 팝업, 상태별 화면) 디자인을 따른다. 우측 하단 토스트, 카드 1~3장
  - 목업에는 모바일 디자인이 없으므로 반응형(5장) 결정에 따라 **좁은 화면 레이아웃은 새로 정한다** (11_SCREEN_SPEC.md SCR-001 상세 설계 때 와이어프레임으로 확정)
- 결정일: 2026-11-24 (모바일 보완 2026-11-25)

## 4. API 통신

### HTTP 클라이언트 / 공통 처리
- 상태: ✅ 결정
- 선택지: fetch 래퍼 / axios (+ 인터셉터로 토큰·에러 공통 처리)
- 결정: `fetch` + `api.ts`의 작은 공통 함수 하나 — 에러 규약(`{"error": {"code", "message"}}`) 파싱만 담당. SSE는 `EventSource`
- 결정일: 2026-11-25

### API 타입 관리
- 상태: ✅ 결정
- 선택지: 수동 타입 정의 / OpenAPI 코드 생성 / 백엔드와 타입 공유
- 결정: **수동 정의** (`src/types.ts`). FastAPI `/docs`를 기준으로 작성하고, API 응답이 바뀌면 같은 작업 안에서 갱신
- 이유: 응답 타입이 몇 개뿐. SSE 이벤트 형식은 OpenAPI에 나오지 않아 자동 생성해도 일부는 수동이 됨
- 결정일: 2026-11-25
