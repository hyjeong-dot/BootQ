# 99. 결정 변경 이력

> 이미 ✅로 확정된 결정을 **변경**할 때만 기록한다. (최초 결정은 각 문서에 기록되므로 여기 쓰지 않는다)
> 목적: 나중에 "왜 이렇게 바꿨더라?"를 추적하고, AI가 과거에 폐기된 방안을 다시 제안하지 않게 한다.

## 폐기된 방안 (다시 제안 금지)

> 검토했지만 명확한 이유로 폐기한 방안. AI는 아래 방안을 다시 제안하지 않는다.

| 방안 | 폐기 이유 | 날짜 |
|---|---|---|
| 헥사고날 아키텍처 | 순서대로 이어지는 Python 파이프라인이라 Port 계층 비용이 큼. 경계는 LLM 공급자·캠프 출처에만 둔다 (02_BACKEND.md) | 2026-11-24 |
| 가중합 적합도 점수로 정렬 | 보상 효과로 직무가 틀린 캠프가 산업·유사도 점수로 올라옴 (인턴십의 주된 오류). 사전식 정렬 사용 | 2026-11-24 |
| 매 요청 LLM에 캠프 전체 목록을 주고 고르게 하기 (메인 경로) | 요청당 토큰·응답 시간이 큼. 평가 비교군 ③으로만 사용 | 2026-11-24 |
| 고민 원인 intent 6종 분류 + camp_type 매핑 테이블 | camp_type과 1:1로 맞지 않음. 슬롯필링이 desired_help를 camp_type 값으로 바로 추출하고, UNKNOWN이면 category 기본값으로 보완 | 2026-11-24 |
| 산업 하나 = 계열 하나 (dict) 구조 | 한 산업이 여러 계열에 속함 (예: 유통/물류는 유통·커머스와 물류·무역). `산업 → 계열 집합` 사용 | 2026-11-24 |
| 캠프 ID에 직무코드 포함 | 같은 캠프가 두 번 추천될 수 있음 | 2026-11-24 |
| Gemini 사용 | 무료 티어 입력이 학습에 쓰이고(EU 외), 최신 모델의 일일 한도가 작음 | 2026-11-24 |
| Rust | 병목이 LLM 응답이라 속도 이점이 없음 | 2026-11-24 |
| MongoDB | 데이터가 관계형(직무 관계, 다대다)이라 문서 DB 이점이 적음 | 2026-11-24 |
| 데모 페이지를 Jinja2 서버 렌더링으로 (SSE로 HTML 조각 전송) | 추천이 SSE로 뒤늦게 와서 클라이언트 JS가 어차피 필요하고, 실서비스 연동 계약은 JSON이어야 함 (03_FRONTEND.md) | 2026-11-25 |
| 인턴십 👍/👎 라벨을 정답으로 사용 | 버전별 출력에 대한 판정이었고 측정 도중 기준이 바뀌었음 (EVAL.md) | 2026-11-24 |

> 폐기가 아니라 **보류**인 것 (조건이 맞으면 다시 검토): 임베딩 유사도 정렬, SQL 상위 10개 안 LLM 재정렬, 전자·반도체 산업 계열(E13 비교 후 결정), pgvector.
